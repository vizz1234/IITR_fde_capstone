Prompt Library & Specification

Prompts are treated as version-controlled software artifacts. Every prompt is designed with Role Scoping, Strict Output Formatting (JSON or enforced citations), and Strict Grounding (blocking the model from inventing ungrounded claims).

3.1 Prompt Library Catalog

PRMPT-CLS-001 — Intent & Urgency Classifier (v1.0)

Target Component: src/classify.py  |  Output Schema: Enforced JSON containing intent, urgency, confidence, reasoning, and alternatives_considered.

You are an expert AI ticket classifier for CloudServe Solutions.
Analyze the support ticket subject and body, then classify it into:
  1. Intent (must be one of 22 valid intent categories)
  2. Urgency (low, medium, high)
  3. Confidence (float 0.00 to 1.00)
Return ONLY valid JSON. No additional commentary or prose.

PRMPT-GEN-001 — Grounded RAG Generator (v1.0)

Target Component: src/generate.py  |  Output Constraint: Must cite exact document IDs [DOC-XXX-001]. Must state "unable to find information" if context does not support the claim.

You are a helpful support engineer at CloudServe Solutions.
Strict Grounding Rule: You MUST answer the question using ONLY the retrieved documentation context.
Citations: Include inline citations [DOC-XXX-001] for every claim made.
If the retrieved context does not contain sufficient information, state clearly:
"Based on available documentation, I was unable to find a specific answer."

PRMPT-GRD-001 — Guardrail Validator (v1.0)

Target Component: src/guardrails.py  |  Execution Rule: Deterministic regex + heuristic validator. Does not use an LLM — fully deterministic for reliability and speed.

3.2 Prompt Quality & Safety Checklist

✅Versioned in version control (prompts/README.md)
✅Zero credential exposure in prompt strings
✅Anti-hallucination grounding instructions included
✅Automated fallback parsing logic implemented

System Architecture & Technical Design

The system implements 6 sequential pipeline components built over 3 persistence and infrastructure layers, exposed through a FastAPI web API. The design prioritizes determinism, auditability, and safety over raw automation volume.

4.1 Pipeline Architecture Diagram

4.2 Component-by-Component Description

1
Ingest — Multi-Channel Normalization
src/ingest.py
Normalizes payloads from all 4 channels (Email, Live Chat, Docs Comments, Community Forum) into a unified Ticket schema. Preserves subject, body, customer tier, and language fluency metadata for downstream processing.
2
Classifier — Intent & Urgency Prediction
src/classify.py
Predicts intent across 22 categories and urgency (low, medium, high) with a calibrated numeric confidence score in [0.00, 1.00] and structured reasoning. Includes graceful fallback on LLM failure to prevent pipeline crashes.
3
Retriever — Chroma Vector Semantic Search
src/retrieve.py
Searches documentation.json (29 articles) using Chroma vector store and all-MiniLM-L6-v2 dense embeddings. Applies a 0.35 similarity score threshold — returns empty passage set if no doc exceeds threshold, triggering clean escalation instead of forcing irrelevant context into generation.
4
Router — Deterministic Threshold Routing
src/route.py
Applies a hard 0.80 confidence threshold. Mandates escalation for security_incident, compliance_request, feature_request, data_residency, or must_not_auto_respond flags regardless of confidence. For escalations, generates a rich EscalationPayload with summary, intent, urgency, retrieved docs, and specific uncertainty reason for Tier 2 engineers.
5
Generator — Grounded RAG Response Drafting
src/generate.py
Drafts responses strictly grounded in retrieved passages from the vector store, appending verifiable inline citations [DOC-XXX-001] for every claim. Includes programmatic fallback citation injection to ensure citation compliance even when the LLM omits document ID strings.
6
Guardrails — Safety & Validation Suite
src/guardrails.py
Deterministic safety suite checking: PII leakage (regex patterns for API keys including hyphenated sk-or-v1-..., bearer tokens, credit cards), hallucinated citations (unverified doc IDs), and tone. Can issue a BLOCK action preventing any unsafe response from reaching a customer.
L
Decision Logger — Complete Audit Trail
src/logging_store.py → storage/decisions.db
Records 100% of automated decisions to SQLite storage/decisions.db, including: ticket ID, stage, prediction, confidence, threshold applied, action taken, human-readable reason, sources used (JSON array of doc IDs), guardrail validation status, prompt version, and traceable PRD requirement IDs.

7.4 Incident Response Procedure & Runbook

Incident Severity Levels

  • SEV-1 (Critical): PII leak or inaccurate financial/security answer sent to a customer.
  • SEV-2 (Major): System error rate >5% or latency >10 seconds.
  • SEV-3 (Minor): Non-blocking classification degradation.

SEV-1 Immediate Action Runbook (2 AM Responder Guide)

  1. Activate Kill Switch: Set CONFIDENCE_THRESHOLD=1.0 in .env to force 100% ticket escalation to human agents immediately.
  2. Isolate Incident: Query the decision log to identify affected responses:
    SELECT * FROM decisions
WHERE action_taken = 'AUTO_ANSWER'
ORDER BY created_at DESC
LIMIT 50;
  3. Notify Stakeholders: Notify Head of Support and Legal/Compliance team within 15 minutes.
  4. Post-Mortem: Conduct root cause analysis on the failed guardrail/retrieval within 24 hours of resolution.

7.5 System Kill Switch Mechanism

Kill Switch Method 1
Environment Flag
Setting CONFIDENCE_THRESHOLD=1.00 in .env causes all incoming tickets to escalate cleanly to Tier 2 human support — no AI auto-answering occurs.
Kill Switch Method 2
Mock Mode Override
Setting USE_MOCK_LLM=true immediately redirects all model completions away from external providers, isolating the system from any LLM API during an outage or investigation.

8.1 Summary of Requirement Revisions (PRD v1.0 → v2.0)

Req IDOriginal Spec (v1.0)Revised Spec (v2.0)Justification & Empirical Evidence
F6 — RoutingConfidence threshold fixed at 0.70.Confidence threshold raised to 0.80.Mid-sprint validation showed 0.70 allowed borderline intent classifications (0.72–0.78) to auto-respond, causing 4.2% unsupported claims. F4 — RetrievalVector retrieval top_k = 3 without score thresholding.Vector retrieval top_k = 5 with similarity score threshold (0.35).Returning top 3 unconditionally forced irrelevant passages into generation for novel tickets. 8.2 Failed Assumptions Log

❌
Assumption 1 (Failed): LLM system prompt alone would guarantee 100% citation compliance.
Reality: LLMs occasionally generated accurate answers but omitted document ID strings [DOC-XXX-001].
Fix: Implemented programmatic fallback citation injection in src/generate.py matching retrieved source IDs directly to the response post-generation.
❌
Assumption 2 (Failed): External LLM APIs would be 100% available during unattended evaluation.
Reality: OpenRouter rate limits can throttle free tier usage during batch runs, causing pipeline crashes.
Fix: Built USE_MOCK_LLM fallback provider in src/llm.py so unattended runs degrade gracefully without crashing (satisfying Acceptance Criterion A11).

8.3 Engineering Reflection

💡
Building an AI engineering pipeline for enterprise support requires prioritizing trust over automation volume. Escalating an uncertain ticket with structured documentation context attached is an operational success — it empowers a Tier 2 engineer with information to resolve faster. Auto-answering with an ungrounded or hallucinated claim damages customer trust in ways that are difficult to recover from. The 0.80 confidence threshold embodies this principle: the system is designed to know what it doesn't know.
§ 9

Strategic Recommendations for CloudServe Leadership

Based on the discovery findings, system evaluation results, and engineering lessons learned, the following four strategic recommendations are presented for CloudServe leadership consideration:

  • Deploy RAG Triage Immediately

    Deploying the RAG triage pipeline will immediately absorb approximately 55% of incoming ticket volume, reducing response times for standard queries from 10 hours down to under 3 seconds. This directly addresses the SLA breach and customer satisfaction issues identified in discovery.

  • Adopt Structured Escalation Payloads as Standard Procedure

    Requiring Tier 1/AI to pass structured escalation payloads — containing ticket summary, retrieved documentation context, and specific uncertainty reason — will cut Tier 2 resolution times significantly. Daniel Okonkwo estimated that context-free escalations waste approximately 50% of Tier 2 engineer time on re-investigation.

  • Deprecate Personal Snippet Files Across Support Team

    Require all support staff to reference and update the central 29 documentation articles as the single source of truth. Document citations in outbound emails will allow Ines Varga's technical writing team to identify and patch documentation gaps directly, continuously improving knowledge base coverage and quality.

  • Maintain the 0.80 Confidence Threshold — Resist Lowering It

    Resist the temptation to lower the confidence threshold below 0.80 to inflate automation numbers. Maintaining 0.80 preserves customer trust, prevents hallucinated responses, and aligns with Marcus Adeyemi's explicit requirement that the system "prefer silence over confident incorrect answers." The current escalation rate of 45% is operationally beneficial — those escalations now arrive with rich context payloads that accelerate Tier 2 resolution.
