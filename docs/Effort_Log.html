Where the Time Went Unexpectedly

Which task took far longer than you expected, and why?
The PII guardrail in src/guardrails.py took longer than planned, specifically because of hyphenated API key formats. The initial regex pattern matched alphanumeric tokens correctly but CloudServe API keys use a sk-or-v1-... format with multiple hyphens that the standard pattern skipped entirely. I only discovered this when I wrote a specific engineered payload test with a real-format key and the guardrail passed it. An additional 45 minutes was spent understanding the exact format and updating the regex to a multi-pattern approach. It was a small item in isolation but a reminder that security-sensitive regex needs adversarial test cases from the start, not after the unit tests are already written.
Which task was easier than you expected, and why?
The Chroma vector store setup (src/retrieve.py) was significantly faster than estimated. I had budgeted 8 hours expecting preprocessing challenges with the knowledge base data, but documentation.json was already structured with consistent fields and clean text. Embedding and indexing 29 articles took under 30 minutes, and the score thresholding logic was a single filter operation rather than the custom re-ranking logic I had initially planned. The only hiccup was a chromadb version conflict that took about 20 minutes to resolve with version pinning, but overall the component was ready a full day ahead of schedule.
What would you allocate differently if you started again on Monday?
I would front-load adversarial testing for the guardrail component and write the PII test cases before implementing the regex, not after. More broadly, I would allocate time for a mid-sprint mini-evaluation run (which I ended up doing organically in Week 3) and schedule it explicitly in the sprint plan as a backlog item. The threshold change from 0.70 to 0.80 was only discovered through this mid-sprint run — had I not done it, the final evaluation would have included unsupported auto-answers that would not have been caught. Building in one deliberate validation checkpoint per week would be the structural change I would make.
What did you spend time on that turned out not to matter?
I spent about 45 minutes early in Week 2 designing a custom re-ranking layer on top of Chroma's vector search, with plans to weight passages by document age and citation frequency. Once I saw that the 0.35 similarity score threshold already produced clean, relevant passage sets for 100% of answerable topics in the dev set, the re-ranking layer was unnecessary. It was straightforward to drop, but the design time was not recoverable. The lesson is to validate the simplest version of a component against real data before adding complexity.
